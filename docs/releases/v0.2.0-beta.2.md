# Skanda Radiology v0.2.0-beta.2

This beta fixes imaging workflow, accessibility and account-recovery gaps found after beta.1.

## Changes

- Verified X-ray import, display adjustments, fit/reset and mobile navigation with a public test image; added desktop/mobile screenshots.
- Unified shell, viewer and report buttons with shadcn; added Radix modal isolation, focus restoration and keyboard tabs. Fixed mobile toolbox overlap.
- Added explicit NRRD acquisition context and metadata-bound analysis/resume identities. CT Skanda requests require confirmed calibrated HU values.
- Imported supported conventional DICOM frames with source frame/series identity and strict unsupported-object checks.
- Hardened model streaming termination/error/cancellation handling and compatible-server connection detection.
- Added current-password changes, short-lived administrator-issued recovery codes, session revocation and recovery concurrency protection.
- Added process-level server metrics, explicit capability flags and an authenticated load-smoke harness.

## Packages

- `skanda-radiology-v0.2.0-beta.2-source.zip`: tagged source and Compose deployment. Follow `docs/deployment.md`; credentials and model services are not included.
- `skanda-radiology-v0.2.0-beta.2-web.zip`: prebuilt local-only frontend. Serve over HTTP with separately configured model/API proxy services as needed. It does not enable server accounts by itself.
- `SHA256SUMS.txt`: SHA-256 checksums of both archives.

## Verification and limitations

Frontend tests, lint and production build pass. Server unit/integration and load-smoke results are documented in the validation records. Controlled model responses test software behavior, not clinical performance. No inference engine is currently available, so live inference remains unverified.

SSO/MFA, geometric DICOM-series/PACS integration, hosted full-volume object storage, tenant isolation and durable server inference workers remain unimplemented. Full accessibility/physical-device testing, production operations and independent clinical validation remain release gates. See `docs/validation/2026-11-10-swarm-followup.md` and `server/capabilities.json`.
